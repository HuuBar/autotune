# 知识工程流水线 · 交接总纲（agent 集群任务包 v1.0）

> **读我 first**。你们负责实现一套"知识工程流水线"：执行前把知识编排成分层图，执行时按图行走，执行后写回增殖。设计已定型，你们的任务是**实现 + 测试**，不是重新设计。
> **总原则**：严格按 `01_知识工程架构设计_v1.md` 的语义实现；语义有疑问时上报，不要自行发明替代语义。

## 1. 背景一分钟

我们在造一个 ML 自动优化系统的前端：把"模型即兴规划"改造为"知识编排成图 → 按图执行 → 结果回写"。后端执行系统（autotune）已存在，本次**不需要碰它**，只需要实现前端流水线的离线部分。

**关键便利**：本包全部模块都**不依赖**真实训练环境、模型 API、Docker——用 mock 执行器即可开发测试（架构文档第 7 节）。环境接入（L2 级）不在本次范围。

## 2. 模块分解（M1~M5，标注依赖）

| 模块 | 内容 | 依赖 | 可并行 |
|---|---|---|---|
| **M1** | 编排图 schema + 确定性校验器（validator） | 无 | 可 |
| **M2** | dry-run 调度模拟器（按执行语义走图，mock 执行器） | M1 | 可（用夹具图先行） |
| **M3** | 假说账本与回写模块（hypotheses.jsonl + 后验更新 + 领域聚合） | M1 | 可 |
| **M4** | 编排编译器（知识卡库 + 任务书 + 地形 → 图，LLM 离线调用 + 校验门） | M1（M2 联调后置） | M1 后 |
| **M5** | 端到端测试与示例复现（用黄金夹具跑通"编译→校验→模拟执行→回写"全链） | M1~M4 | 最后 |
| **M6** | 量化评测台：事故剧本库 + 有/无编排 A/B 对照 + 指标计算（见 `03` 文档第四部分） | M2、M3 | M5 后 |

**开工前必读顺序**：`01_知识工程架构设计_v1.md`（语义）→ `03_架构全景_时间线推演与量化评测.md`（生命周期的逐拍实例，理解语义怎么"活"起来）→ `02_示例编排图_tbox.yaml`（夹具）。M1~M5 的语义若与 `03` 的时间线推演冲突，上报而非自选。

## 3. 各模块验收标准

### M1 schema + 校验器
- 定义四层节点（goal/domain/hypothesis/action）与四类边（requires/informs/alternatives/no_parallel）的机器可读 schema（YAML/JSON）；
- 校验器确定性检查：DAG 无环、requires 指向存在节点、每个 action 有 verify、alternatives 组完整、goal.acceptance 每条可解析为断言、决策点分支条件完备；
- **验收**：`02_示例编排图_tbox.yaml` 通过校验；构造 ≥6 个含各类错误的坏图，全部被拦截并给出可读错误信息。

### M2 dry-run 调度模拟器
- 实现执行语义 E1~E8（架构文档第 4 节），逐条对应测试；
- mock 执行器：按动作 type 返回预制产物（可配置成功/失败序列）；
- **验收**：跑黄金夹具，输出执行轨迹日志，能演示：前置解锁顺序、J1/J2 决策分支（改 mock 产物可切换分支）、no_parallel 不被共调度、失败→重试→blocked 升级、早停触发。

### M3 账本与回写
- 按 `writeback.record_schema` 追加写 hypotheses.jsonl；实现后验更新（confirmed/refuted → posterior）与按领域聚合收益的报告函数；
- **验收**：模拟跑完黄金夹具后账本内容正确、聚合报告正确；非法写回（缺字段）被拒绝。

### M4 编排编译器
- 输入：知识卡库（本包 `参考/自动化ML优化战术知识卡_v1.md`）+ 任务书 + 地形描述 → 输出编排图；
- 产出必须过 M1 校验器才放行；编译器同时输出"卡片采用/拒绝论证"；
- **验收**：以 TBox 任务书为输入，产出图通过校验，且领域层覆盖 ≥3 个正交方向、每个假说有机制解释与先验；LLM 可选用任何 OpenAI 兼容接口（端点由配置注入，不写死）。

### M5 端到端测试
- 一键脚本跑通：编译（可用缓存的 LLM 输出）→ 校验 → 模拟执行 → 回写 → 聚合报告；
- **验收**：`pytest` 全绿 + 一键脚本退出码 0 + 产物齐全（图、轨迹日志、账本、报告）。

## 4. 工程要求

- Python 3.10+，核心逻辑零第三方依赖（yaml 可用 PyYAML）；LLM 调用封装为可替换的客户端接口；
- 分支 `feat/knowledge-pipeline`，每模块独立 commit（Conventional Commits，标注模块号）；
- 全部完成按 `报告模板.md` 回传：模块状态、commit、测试输出、**新发现**（实现中发现的 schema/语义问题，列出来不要擅自改设计）。
