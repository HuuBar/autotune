## 2. 三十秒摘要

按架构设计 v1 实现了执行前的"知识编排成图 → dry-run 按图执行 → 结果回写"全链路，并在 6 个事故剧本上做了有/无编排的预登记 A/B：信息缺失事故 0 vs 7、噪声当战果 0 vs 3、盲抄 0 vs 3、决策分支正确率 100% vs 83%、S4 小样本阈值陷阱识别 1.0 vs 0.0。**当前全部是离线 mock 环境（L1），未接真实训练后端——这是设计使然，不是缺口隐瞒。**

## 5. 提请算法团队裁决的问题（附工程侧预设立场）

- **Q1 后验更新公式**（confirmed→p+(1-p)·0.9，refuted→p·0.1）：工程默认值，锚点是架构全景文档里"H1 prior 0.5→0.95"的唯一实例。已实现为单一函数 `ledger.update_posterior`，**改公式只需动一处**。请算法给出有理论依据的更新规则（Beta 共轭？按证据强度分级？）。
- **Q2 假说终态聚合**：任一动作 blocked→假说 blocked；全 confirmed 后按 run 产物收益判定（≥0.05 confirmed / ≤0 refuted / 中间复跑后 uncertain）。0.05 边际阈值是拍的。请给出判定规则的正式形式。
- **Q3 E8 写回粒度**：架构文档字面是节点级"写回完成前不得解锁下游"，我们实现为假说级（账本词表只支持假说级记录）。同假说内 A1→A2 是"先执行后写回"。**若算法认为必须节点级，请先扩展账本词表**——这是设计约束不是实现懒惰。
- **Q4 调度优先级**（预期收益中值/验证成本）与 E7 早停（连续 k=3 无验收进展）：均为可配置工程默认值。是否该纳入先验不确定性做探索-利用权衡（如 UCB 式）？这属于算法增量，当前确定性规则保证可复现。
- **Q5 评测基线代表性**：无编排侧是确定性启发式 agent（LLM ReAct 的离线替身），行为按真实失败模式构造。它保证了可重复与归因干净，但**不能声称代表真实模型的全部行为分布**——真实 A/B 属 L2（Exp 2 协议已冻结）。请算法审计 6 个剧本的期望应对是否合理。
- **Q6 决策分支的机器判定**：当前由 playbook 按分支索引注入事实，图内 then 是自然语言。是否需要在 schema 增加结构化 effects 字段（boost/skip 动作列表）？这是下一个 schema 版本的最大候选变更。

## 6. 对可预见质疑的预先回应

**"自己设计图又自己设计剧本，评测是不是自我论证？"**
部分成立，已防御：剧本来自 autotune v1 的真实事故复盘（阈值 0.90 事件等）和知识卡 C 类失败模式，不是为让图赢而构造；指标与期望在跑实验前预登记；双方 facts 逐字节一致。但确实都是"已知陷阱"——对未知陷阱的泛化，需要算法的 Exp 2 真实 A/B 回答，我们不声称 L1 结果能外推。

**"步数没赢，凭什么说有用？"**
预登记立场：编排的主张从来不是"更快"而是"不掉坑"。无编排侧在 S4 只走 3 步恰恰是因为它漏了工序（方向覆盖 1，满分陷阱没识别）。若算法认为应设"单位有效进展的成本"这类指标，评测台可加——metrics 是确定性函数，补一个指标半天工作量。

**"分支条件是自然语言，接真后端时怎么判定？"**
承认这是当前最薄的一层。离线阶段由 mock 环境按事实表判定（可重复）；接后端时需要把决策条件编译为对结构化产物的断言（类似 acceptance 的解析器）。我们倾向把这个做成 schema 的 effects/condition 字段（Q6），而不是让运行时 LLM 自由判读——那会重新引入即兴。

**"为什么不等真实环境再做评测？"**
环境无关开发是架构文档定的策略：mock + 事故剧本让 harness 在 Docker/真实训练可用前就可开发、可回归；且这套测试台在接入真后端后原样变成回归套件。投入不浪费。

**"并行调度是不是被回避了？"**
架构文档明确将并行列为后续阶段。我们的处理是：v1 串行保证语义正确，同时把 no_parallel 冲突全部以 `no_parallel_hold` 事件落盘——并行化时这些就是现成的调度约束和测试断言。
