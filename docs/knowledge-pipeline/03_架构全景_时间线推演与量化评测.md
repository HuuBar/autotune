# 架构全景：知识注入的产生、编排图的生命周期与量化评测

> 本文回答三个问题：① 执行前注入的知识**按什么时间线、经什么环节**产生（每个环节的产物与质量门）？② 模拟执行中，编排图**如何一步步演化**（状态、分支、失败、早停）？③ 如何**量化**"有编排 vs 无编排"的差距？
> 全文以 TBox 案例为时间线实例，与 `02_示例编排图_tbox.yaml` 对应。

---

## 第一部分：执行前——知识注入的产生时间线（T-2 天 → T0）

**核心设计决议**：编译器不需要先知地形。**侦查被编码为图的第一批动作节点**，"未知"被显式表达为 informs 边与决策点——图不是"基于已知的最优路径"，而是"基于未知的探索结构"。这让执行前/执行中的分界干净利落：执行前生产的是"探索结构"，执行中填充的是"事实"。

| 时刻 | 环节 | 谁做 | 输入 → 产物 | 质量门（不过则返工） |
|---|---|---|---|---|
| T-2d 上午 | S1 广泛搜集 | LLM+人 | 任务关键词 → 原始资料池（~40 源） | 查询覆盖：失败模式/实践指南/复盘/评估方法，四类缺一不可 |
| T-2d 下午 | S2 筛选 | LLM | 资料池 → 候选条目 | 三档判决规则（决策改变/动作直给/边界标注）；**弃用项留痕**（为什么弃） |
| T-1d 上午 | S3 整理成卡 | LLM | 候选 → 战术卡库 v1 | 每卡六要素齐全（情境/做法/依据/边界/验证/落点）；人抽审 20% |
| T-1d 下午 | S4a 编译·选卡 | 编译器(LLM) | 卡库 × 任务书 → 采用/拒绝论证表 | 每张采用卡有"为何适用于本项目"，拒绝卡有理由（防盲抄的审计点） |
| T-1d 下午 | S4b 编译·成图 | 编译器(LLM) | 上表 → 编排图 YAML | **确定性校验器全绿**（无环/边合法/动作有 verify/断言可解析）——模型的创造性到此被关进笼子 |
| T0 上午 | 人工评审点 | 人 | 图 + 选卡论证 | 评审清单：方向正交吗？先验离谱吗？有假分支吗？（人只审结构，不替模型做方案） |
| T0 下午 | 注入 | 工程 | 图 → 调度器可读；卡库 → 运行时检索库 | 一键装载，版本号绑定（图版本 ↔ 卡库版本 ↔ 任务书哈希） |

**为什么这个顺序是合理的**：S1~S3 只做"知识"，不碰任务——所以卡库跨任务复用；S4 才碰任务——所以适配成本每次只有编译一次；人工评审放在执行前最后一刻——因为此前全是可回退的离线操作，此后开始消耗真实资源。**每一步的交付物都是带 schema 的文件，交接不靠对话**——这是架构能被 agent 集群执行的前提。

## 第二部分：执行中——编排图的演化时间线（模拟执行逐拍推演）

剧本设定：mock 环境内置事故剧本（断链存在、数据有重复列、验证集游戏类 320 条、H3 加权仅有边际提升）。`→` 为调度器动作，`◆` 为图状态变化。

```
T+0   → 解锁计算：A1/A3/A4 无前置 → ready；按"成本/预期收益"选 A1（最便宜且杠杆最大）
T+1   → A1 执行（mock 返回 wiring_report：存在 1 处未接线）
      ◆ H1 状态 running；产物落盘
T+2   → 决策点 J1 读 wiring_report：分支"存在未接线"命中 → A2 提为最高优先
      （条件判定与理由写入决策日志——不许暗箱分支）
T+3~4 → A2 修复 + 冒烟验证（mock：第一次冒烟失败 → retry 1/2 → 第二次通过）
      ◆ H1: confirmed，posterior 0.5→0.95；账本追加第 1 条
T+5   → A4 数据体检（mock：发现重复列）◆ known_issues +1；A5/A7 的前置随之满足
T+6   → A3 误差结构分析（mock：FP 主导，游戏类验证样本 320 条）
T+7   → 决策点 J2：FP 主导 且 样本<500 → 走"A5 阈值路线，但 A6 验收升级为 K 折"
      ◆ H6（稳健性假说）被分支条件自动激活——图在响应事实而演化
T+8   → A5 编辑（单原子；改配置后当场 JSON 校验，通过）→ A6 全量训练
      ◆ H2: confirmed，实测 +0.12，账本第 2 条
T+9~10 → A7/A8（no_parallel 约束：与 A5/A6 串行，同口径预算）
      ◆ H3: 实测 +0.03 → 触发"边际提升复跑"规则 → 复跑 +0.01 → 判 "uncertain"，
      账本记"不计入战果"——指标纪律在流程内，不靠自觉
T+11  → 验收断言机读核对：5 条全过 → 主目标达成
T+12  → 继续探索 D3（H5 剔特征）或满足早停规则（连续 k=3 无进展）→ 停止并报告
```

**失败路径演示（并行宇宙）**：若 A2 重试 2 次仍失败 → `blocked` → 升级：调度器不静默跳过，而是标记 H1 blocked、冻结其下游、继续走 D2 假说、并在终报中单列"未决阻塞"交人裁决。**失败是图内的一等公民状态，不是异常。**

## 第三部分：执行后——回写与下一轮（P4 的真实运转）

1. **账本**：hypotheses.jsonl 追加 5 条（confirmed×2、uncertain×1、blocked×0、未验×2），每条带证据路径；
2. **领域聚合**：接线域（D1）确认高收益 → 下轮 prior 上调；特征域（D3）未探索 → 保留；加权域边际 → 降权；
3. **卡片增殖**：本轮新知（"验证样本<500 时阈值必须 K 折"）写成既有 B7 卡的边界补充，**provenance=本轮已验证**——未验证的观察标"待验"，防记忆回授污染；
4. **重编译**：下轮以"更新后的先验 + 账本 + 新增 known_issues"为输入重跑 S4——**图每轮重生**，不维护一份越改越乱的死图。

## 第四部分：量化评测设计（有编排 vs 无编排）

### L1 离线 dry-run A/B（主力，不依赖真实环境）

- **测试台**：mock 环境 + **事故剧本库**（每个剧本 = 触发条件 + 环境响应 + 期望应对）：
  S1 断链｜S2 重复列名｜S3 脆弱 JSON｜S4 小样本阈值陷阱（验证集满分）｜S5 边际提升噪声｜S6 沙箱依赖缺失。
- **对照**：同一剧本下，(a) 按图执行的 agent vs (b) 自由 ReAct 的 agent（仅有任务书）。同一底座模型，唯一变量是编排。
- **预登记指标**：
  | 指标 | 无编排基线预期 | 有编排目标 |
  |---|---|---|
  | 到达验收的总步数 | 剧本实测 | 显著更少 |
  | 信息缺失型事故（先决策后补查） | 实测 | 0~1 起 |
  | 探索方向覆盖数 | 实测 | ≥3 正交方向 |
  | 决策点分支正确率 | — | 100%（条件判定） |
  | S4 陷阱识别率（阈值满分被追问） | 实测 | 识别并升级验收协议 |
  | S5 噪声当战果的次数 | 实测 | 0 |
  | 盲抄（与剧本不符的卡片套用） | — | 0 |
- **归因原则**：过程指标为主判据；每个剧本独立计分再聚合（防单剧本运气）；剧本对双方完全一致（可重复性是本测试台的核心价值——**它就是 harness 的回归测试套件**）。

### L2 真实 A/B（环境打通后）

即已冻结的 Exp 2 协议（`02_实验设计书_Gate0.md`）：L1 通过后再上，避免用真金白银测未经验证的设计。

## 第五部分：与共识框架的对照自检

| 共识 | 本文如何遵守 |
|---|---|
| C-01 不套技术 | 全部组件从"理想流程需要什么"推导；无一对标复制 |
| C-02 内容 vs 过程 | 卡库=内容，图=过程结构，调度=过程执行 |
| C-03 智能前移 | 创造性集中在离线 S4；运行时只做解锁/判条件/验证 |
| C-04 假设=信息需求 | 侦查节点是图的首批居民；informs 边承载信息前置 |
| C-05 两类未知 | 信息需求→recon 节点；真实验未知→run 节点与 alternatives 分支 |
| C-06 不单设地形层 | 地形由 A1/A3/A4 节点产出，直接写回图 |
| C-07 分工 | 前端（本架构）与 autotune 后端只经薄适配层 |
| C-08 试验场 | L1 测试台不依赖 TBox 环境；L2 复用 Exp 2 协议 |
