## 3. 新发现（schema/语义/设计问题，未擅自修改）

### 已裁决回写 SPEC（裁决方向：黄金夹具为 schema 实例基准）
1. **requires ↔ decision**：黄金夹具有 `requires: A3→J2`。裁决：允许 requires 指向 decision（决策点以前置产物为输入），禁止来自 decision。若上游裁决相反，validator 三处放宽需回调（代码注释已标注）。
2. **节点 title**：黄金夹具 action 全省略 title → 不作硬性必填。
3. **else 分支形态**：J1 的 else 无 then 键 → else 值本身即兜底动作描述。
4. **后验更新系数 0.9**（confirmed→p+(1-p)·0.9，refuted→p·0.1，uncertain/blocked 不变）为工程默认值，锚定 03 文档 H1 0.5→0.95；唯一实现 `ledger.update_posterior`。
5. **未验假说不落账本**：03"账本追加 5 条（未验×2）"与状态词表冲突，裁决为未探索领域由 domain_report 经图映射给 hold。由此账本实写 4 条（H1/H6/H2/H3），与 03"5 条"口径有偏差。
6. **账本收益键统一为 `gain`**：修复 M2（写回键 measured_gain）↔M3（聚合默认 gain）口径错位；playbook 产物层键不变，写回时归一化。
7. **E8 写回粒度**：01 §4-E8 字面为节点级，实现为假说终局裁决粒度（账本词表只支持假说级记录所迫），有序性仅在假说边界严格成立。同假说中间动作链"先执行后写回"。若要求严格节点级 E8，需先扩展账本词表支持动作级记录。【终审 Major-2，已回写 SPEC §4.2】
8. **E3 分支效果的机器映射无 schema 承载**：then 是自然语言，playbook 按分支索引显式给 boost/skip，缺省时退化为 then 文本内已知 action id 扫描。**建议下版 schema 在 decision.branches 增加结构化 effects 字段（需设计侧裁决）。**

### 工程默认值（实现层，已写入代码 docstring）
9. 假说终态聚合展开：任一动作 blocked→blocked；全部动作 confirmed 后按 run 产物收益判定（≥边际阈值 0.05→confirmed；≤0→refuted；(0,阈值) 复跑用尽→uncertain；无实测口径→机制性 confirmed）。
10. E7"无验收进展"：裁决时刻重估全部验收断言，无"新通过"记一次；开跑已过项不计。E2 tie-break 按 id 升序。E4 串行操作化为 ready 候选集内对端推迟 + no_parallel_hold 落盘。
11. total_gain 仅计 confirmed 记录的 metrics["gain"]（uncertain"不计入战果"）。边际阈值 0.05、复跑 1 次、max_ticks=1000、k 默认 3 为默认值。
12. M6 离线基线为确定性启发式 agent（替代 LLM ReAct）；步数口径=动作执行次数（非 tick，避免系统性偏袒编排侧）；bench 用 k=5 以走完边际复跑剧情；S1~S5 共享黄金图+playbook 深合并覆盖，S6 专用图。
